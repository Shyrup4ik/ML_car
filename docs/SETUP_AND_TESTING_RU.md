# Полная инструкция по установке, новым весам и проверке AVTO

Дата подготовки: 08.11.2026. Инструкция описывает веб-интеграцию `b8aeb84` и текущие корневые скрипты ML. Основной сценарий — **новая модель и новые веса**. После изменения архитектуры или формата файлов сначала выполняй проверку совместимости из раздела 5.

## 1. Что уже сделано

В проект добавлены:

- Русскоязычный frontend: адаптивное оформление, плавные переходы, изображение автомобиля, загрузка и перетаскивание фотографии.
- Вставка скопированной картинки через ⌘V / Ctrl+V и кнопку «Вставить фото». Предварительно сохранять фото в файл не требуется.
- Backend FastAPI: проверка файлов и параметров, распознавание, ручное исправление характеристик, расчёт стоимости и данные для графиков.
- Загрузка моделей один раз при запуске и повторное использование. Веб-распознавание сейчас выполняется на CPU.
- Поддержка схемы одиночной ConvNeXt-Tiny и текущей схемы ансамбля: усредняются вероятности сетей, а не их исходные выходы.
- Подключение текущего CatBoost со справочником `Specs`; восстановление имён классов при чтении сохранённых моделей.
- Статус ошибки вместо завершения сервера при несовместимом файле цены.
- Отображение отсутствующих метрик как «не измерялась» вместо ошибочных 0%.
- Локальное описание API `/docs`, файлы зависимостей веб-приложения и тестов, запуск через `run.py` и `start.command`.

Корневые `train.py`, `predict.py`, `compare_prices.py`, `best_params.json` и исходные ML-зависимости при добавлении сайта сохранены.

**Что проверено:** при подготовке веб-интеграции прошли 26 автоматических проверок. Они проверяют API и загрузочную логику на тестовых примерах. Они не подтверждают точность нового обученного ансамбля и не заменяют запуск с его настоящими весами.

**Что ещё требуется:** получить новые веса, зафиксировать их версии, проверить совместимость, выполнить полный расчёт на сайте и независимую оценку точности. Обучение новых пользовательских весов в рамках веб-интеграции не проводилось.

## 3. Получить актуальный код

Нужны Git и Python 3.12. Выполняй команды в терминале своего компьютера.

Если они не установлены, возьми Git с [официальной страницы](https://git-scm.com/downloads), а Python — с [python.org](https://www.python.org/downloads/), выбрав версию 3.12 для своей ОС. После установки открой новый терминал. На Windows проверь `git --version` и `py -3.12 --version`, на macOS/Linux — `git --version` и `python3.12 --version`.

Если рядом уже есть старая папка проекта, создай новую копию с другим именем. Это позволит сохранить работающую версию и её веса:

```sh
git clone https://github.com/Shyrup4ik/ML_car.git ML_car-current
cd ML_car-current
git log -1 --oneline
```

Для обновления уже существующей копии сначала посмотри состояние:

```sh
git status
git branch --show-current
git pull --ff-only origin main
```

Если есть свои изменения или Git сообщает о расходящихся историях, сохрани старую папку и сделай отдельное клонирование. Не используй `reset --hard` и принудительную отправку для обычного обновления.

Запиши вывод `git rev-parse HEAD`: это версия кода, с которой будут проверяться новые веса.

## 4. Установить окружение

### macOS / Linux

Из папки проекта:

```sh
python3.12 --version
python3.12 -m venv .venv
.venv/bin/python -m pip install --upgrade pip
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python -m pip check
```

`requirements-dev.txt` включает веб- и ML-зависимости. Если нужны только запуск и работа сайта, вместо него можно установить `requirements-web.txt`.

### Windows, PowerShell

```powershell
py -3.12 --version
py -3.12 -m venv .venv
.venv\Scripts\python.exe -m pip install --upgrade pip
.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.venv\Scripts\python.exe -m pip check
```

Активация окружения не обязательна: полный путь к Python гарантирует использование нужного окружения. Во всех следующих примерах для Windows заменяй `.venv/bin/python` на `.venv\Scripts\python.exe`.

### Если обучение будет на NVIDIA

Выбери подходящую установку PyTorch для своей ОС и CUDA на [официальной странице](https://pytorch.org/get-started/locally/). Команду установки выполняй через Python из `.venv`, а не через случайный системный `pip`.

Проверка:

```sh
.venv/bin/python -c "import torch; print('torch:', torch.__version__); print('CUDA:', torch.cuda.is_available())"
```

Для обучения на NVIDIA ожидается `CUDA: True`. На Mac значение `False` нормально: текущий скрипт выбирает CUDA или CPU и не использует MPS. Доступность CUDA не меняет текущий веб-адаптер: он загружает веса на CPU.

## 5. Получить и проверить новые веса

Попроси у человека, обучающего модель, комплект:

1. Новый `car_model.pt`.
2. Новый `price_model.joblib`, совместимый с текущей ML-частью.
3. Версию кода обучения, версии Python и библиотек.
4. Дату обучения, список классов, описание данных и результаты проверки.
5. SHA-256 обоих файлов, чтобы проверить целостность передачи.

Положи оба файла в корень проекта рядом с `run.py`. Файлы не должны оказаться внутри `data/`, `frontend/` или дополнительной вложенной папки. Загрузка PyTorch/joblib допустима только для доверенных файлов: сериализованные модели могут содержать выполняемые Python-объекты.

### Какой формат поддерживает сайт сейчас

| Файл | Требования текущего загрузчика |
|---|---|
| `car_model.pt`, одиночная сеть | `classes`, `img_size`, `weights`; архитектура ConvNeXt-Tiny |
| `car_model.pt`, ансамбль | `classes`, `img_size`, непустой `members`; у каждого участника `arch` и `weights` |
| Архитектуры участников | `convnext_tiny`, `efficientnet_v2_s`, `resnet50` |
| `classes` | Списки `model`, `color`, `body` в порядке, соответствующем выходам сети |
| `price_model.joblib` | Текущий CatBoost и ключи `model`, `specs`, `new_prices`, `market`, `sales`, `quality` |

**Новое имя файла или свежая дата обучения не гарантируют совместимость.** Если новая модель использует другую архитектуру, другие признаки, иной порядок классов или другую подготовку фото, сначала нужно обновить адаптер и его тесты. Нельзя просто переименовать несовместимый файл.

Старый `car_model.pt` поддерживается только в описанной схеме одиночной сети. Старый файл цены от HistGradientBoosting не подходит: нужен новый CatBoost со `specs`.

Проверка целостности на macOS / Linux:

```sh
shasum -a 256 car_model.pt price_model.joblib
```

Если `shasum` отсутствует, на Linux обычно доступен `sha256sum` с теми же именами файлов. На Windows:

```powershell
Get-FileHash .\car_model.pt -Algorithm SHA256
Get-FileHash .\price_model.joblib -Algorithm SHA256
```

Сравни значения с контрольными суммами отправителя и сохрани их в протоколе проверки. Весов и датасета в Git нет; одного клонирования для распознавания недостаточно.

## 6. Если веса нужно обучить

Если новые готовые веса уже получены и совместимы, переходи к разделу 7.

### Подготовить данные

Используй [официальную страницу DVM-CAR](https://deepvisualmarketing.github.io/) и [указатель в проекте](../data/PUT_DATASET_HERE.txt). Датасет предназначен для некоммерческих исследований и образования.

В `data/` положи:

- `tables_V2.0.zip` — архив таблиц; скрипт умеет извлекать CSV;
- `Confirmed_fronts.zip` — фотографии спереди, если требуется обучение распознавания.

Можно использовать распакованные таблицы: `Ad_table.csv`, `Ad_table_extra.csv`, `Price_table.csv`, `Sales_table.csv`, `Image_table.csv`. Основная таблица объявлений обязательна. Без дополнительных техданных часть признаков останется неизвестной; без таблицы ракурсов соответствующий фильтр не применяется. Архив фотографий не заменяет архив таблиц.

### Сохранить предыдущие результаты

Перед обучением скопируй текущие `car_model.pt`, `price_model.joblib`, `best_params.json`, метрики и графики в отдельную папку, например `.local/backups/before-training/`. Запиши их SHA-256. Останови сайт на время замены весов.

Полное обучение перезаписывает модели. `--price-only` перезаписывает файл цены. `--quick` тоже создаёт и перезаписывает результаты с обычными именами: запускай его в отдельной рабочей копии с отдельными выходными файлами. Быстрые веса не следует принимать за полноценную модель.

### Выбрать команду

| Задача | Команда из папки проекта |
|---|---|
| Обучить только новую модель цены | `.venv/bin/python train.py --price-only` |
| Обучить текущую модель цены и ансамбль | `.venv/bin/python train.py` |
| Разрешить полное обучение на CPU, если CUDA недоступна | `.venv/bin/python train.py --cpu` |
| Быстрый прогон на уменьшенных настройках, в отдельной копии | `.venv/bin/python train.py --quick` |

Для `--price-only` фотографии не нужны, достаточно таблиц. Эта команда не создаёт новые веса распознавания. На Mac полное обучение пойдёт на CPU и может быть длительным. Время из README для конкретной NVIDIA не является гарантией для другого компьютера.

В `best_params.json` уже сохранены настройки. При наличии соответствующего ключа код пропускает Optuna и использует их. Если нужен новый подбор, сделай резервную копию файла и удали только нужные ключи: `price_catboost` и/или `cnn_...`. Сохранённые настройки трёх сетей сейчас одинаковые; это не доказательство независимого подбора для каждой архитектуры.

После обучения проверь наличие файлов, отсутствие ошибок в конце журнала и содержимое метрик. После `--price-only` сквозная ошибка цены по фото не измеряется; сайт должен показать это явно. Точность, перенесённая из старых файлов, сама по себе не подтверждает качество новых весов распознавания.

## 7. Автоматические тесты до запуска

```sh
.venv/bin/python -m pytest -q
```

На версии веб-интеграции `b8aeb84` результат: **26 passed**. Было одно предупреждение Starlette о будущем изменении тестового клиента; оно не было падением теста.

Тесты проверяют:

- выдачу страницы, локальных ресурсов и документации API;
- статус загрузки и временную недоступность вычислений;
- повреждённые, слишком маленькие и слишком большие фотографии;
- неверные параметры, неизвестные значения и недопустимые числа;
- ручное исправление, удаление и независимость сессий;
- схему одиночной сети и ансамбля, усреднение вероятностей;
- сообщение об ошибке несовместимого файла цены без завершения сервера.

Распознавание и часть ценовых расчётов в тестах заменены тестовыми объектами. Даже `26 passed` не доказывает загрузку настоящего нового ансамбля, совместимость конкретного нового CatBoost и высокую точность. Для этого обязательны следующие разделы.

## 8. Запустить сайт

Убедись, что оба файла весов лежат в корне. На macOS / Linux:

```sh
.venv/bin/python run.py
```

На Windows:

```powershell
.venv\Scripts\python.exe run.py
```

На macOS также доступен `start.command`. При отсутствии права запуска используй команду выше либо выдай право: `chmod +x start.command`.

Открой [http://127.0.0.1:7860/](http://127.0.0.1:7860/). Терминал с сервером должен оставаться открытым. Дождись статуса «Готов к оценке». Первый запуск может занять больше времени из-за загрузки моделей и подготовки U2Net.

U2Net скачивается rembg при первом запуске. Для работы без сети заранее положи проверенный файл `u2net.onnx` в `models/rembg/`. Интернет также используется для актуального курса ЦБ; при недоступности курса предусмотрен запасной вариант с указанием даты.

Остановить сервер: Ctrl+C в его терминале. После замены весов нужно запустить сервер заново: работающий процесс хранит прежние модели в памяти.

Если порт занят, сначала проверь, не работает ли уже нужный экземпляр. Для отдельного порта:

```sh
AVTO_PORT=7861 .venv/bin/python run.py
```

На Windows:

```powershell
$env:AVTO_PORT="7861"
.venv\Scripts\python.exe run.py
```

Тогда во всех адресах проверки используй порт 7861. `127.0.0.1` — этот компьютер; на телефоне или другом компьютере данный адрес не откроет сервер на твоём Mac.

## 9. Проверить готовность и реальные веса

Открой [http://127.0.0.1:7860/api/health](http://127.0.0.1:7860/api/health).

| Статус | Что означает и что делать |
|---|---|
| `loading` | Модели ещё загружаются. Смотри журнал и подожди |
| `ready` | Загрузка завершена; можно проверять расчёт |
| `error` | Смотри первую содержательную ошибку в терминале: файл, зависимость, схема весов или U2Net |

Сам по себе HTTP 200 у `/api/health` не означает готовность: смотри поле `status`.

После `ready` открой `/api/metadata`. Проверь, что есть списки `models`, `colors`, `bodies`, числа `recognition_models` и `pricing_models`, курс и метрики. Количество классов у новой модели может отличаться от прежних 85. Отсутствующее значение метрики может быть `null` — это не нулевая ошибка.

Выполни полный сценарий из следующего раздела. Запиши версию кода, SHA-256 обоих файлов, результат, время и ошибки. Это будет подтверждением работы именно нового комплекта весов.

## 10. Ручная проверка интерфейса

Для функциональной проверки можно использовать известное фото автомобиля. Если у конкретного фото неизвестны год и пробег, условные значения проверяют работу формы, но не точность цены.

| № | Что сделать | Ожидаемый результат |
|---|---|---|
| 1 | Открыть страницу | Русский интерфейс, корректная иллюстрация, доступная форма |
| 2 | Выбрать JPG/PNG/WebP | Появляется предпросмотр |
| 3 | Перетащить фото в область загрузки | Фото выбирается без отдельного окна |
| 4 | В браузере выбрать «Копировать изображение», вернуться на сайт, нажать ⌘V / Ctrl+V | Фото появляется без сохранения на диск |
| 5 | Повторить через «Вставить фото» | Изображение принимается; при ограничении доступа доступна вставка с клавиатуры |
| 6 | Скопировать обычный текст и вставить в поле пробега | Текст обрабатывается как ввод в поле |
| 7 | Нажать «Вставить фото» при текстовом буфере | Понятная подсказка, без замены существующего фото текстом |
| 8 | Указать год и пробег, распознать | Появляются модель, цвет, кузов и варианты; неверный ответ фиксируется отдельно как ошибка качества |

| 12 | Изменить пробег или выбранную модель и пересчитать | Обновляются исходные параметры и расчёт; одинаковая цена на отдельных входах сама по себе не доказывает ошибку |

Копировать нужно само изображение. URL, текст ссылки и некоторые элементы страницы не содержат картинку в буфере. Если ⌘V / Ctrl+V не работает, сначала проверь буфер на другом изображении и убедись, что сервер готов.

Для технической проверки открой инструменты разработчика браузера, вкладки Console и Network. После полного сценария не должно быть необработанных JavaScript-ошибок и ответов 500 на обычные корректные запросы. Временный 503 при загрузке моделей — ожидаемое состояние.

## 11. Проверить ошибки и API

Открой [Swagger UI](http://127.0.0.1:7860/docs). Сначала дождись `ready`.

1. Выполни `GET /api/metadata` и посмотри допустимые значения характеристик.
2. Для `POST /api/recognize` нажми Try it out, выбери файл в поле `photo`, затем Execute.
3. При успешном ответе ожидаются `session_id`, `recognition`, `prepared_image`, `background_removed`, `processing_seconds`. В `recognition` есть варианты модели, цвета и кузова.
4. Для `POST /api/estimate` укажи полученный `session_id`, допустимые `model`, `color`, `body`, целый `year` и числовой `mileage_km`. Используй технические значения из API, например `Black`, а не русскую подпись «Чёрный».
5. Проверь ответ: `vehicle`, `valuation`, `charts`, `warnings`, `quality`.
6. Удали сессию через `DELETE /api/sessions/{session_id}` — ожидается 204.
7. Повтори расчёт с удалённой сессией — ожидается 410.

Дополнительные проверки:

| Ситуация | Ожидаемое поведение |
|---|---|
| Файл больше 15 МБ | Отказ; API возвращает 413 |
| Повреждённое изображение или текст под именем JPG | Отказ с понятной ошибкой; API возвращает 422 |
| Изображение меньше 64 × 64 | Отказ; 422 |
| Разрешение больше 30 мегапикселей | Отказ; 422 |
| Год раньше 1990 или позже текущего | Ошибка проверки; до расчёта не доходит |
| Пробег отрицательный или больше 1 000 000 км | Ошибка проверки |
| Недопустимые модель, цвет, кузов | 422 |
| Модели ещё загружаются | 503 для операций, которым они нужны |
| Сессия истекла через 30 минут | Требуется повторное распознавание; 410 при расчёте |

Фотография без автомобиля может пройти проверку формата и получить случайное название класса. Полноценный детектор «автомобиля нет» и надёжный отказ для неизвестных моделей сейчас не реализованы. Это отдельная проверка качества и задача развития, а не подтверждённая функция.

## 12. Проверить новую модель на интернет-фотографиях

Сначала зафиксируй комплект кода и весов. Не меняй его посреди проверки.

1. Подготовь список классов, которые новая модель действительно распознаёт. Список доступных моделей цены может быть шире.
2. Выбери фотографии разных машин и источников. Название и поколение нужно установить по независимому описанию до просмотра предсказания.
3. Раздели поддерживаемые и отсутствующие классы. Отдельно отметь ракурс, поколение и качество снимка.
4. Копируй изображения из браузера и вставляй на сайт. Для этого теста сохранять фотографии в файлы не требуется.
5. Записывай ответ до ручного исправления: первый вариант, три варианта, уверенность, цвет и кузов.
6. Записывай все ошибки. Не заменяй неудачную фотографию более удачной после просмотра ответа.
7. Для цвета и кузова ставь оценку только при известной метке. Неизвестное значение оставляй как «нет метки».

Таблица результатов должна содержать:

```text
№; ссылка на фото; истинная модель; поколение/год, если известно;
есть ли класс в модели; ракурс; первый ответ; второй ответ; третий ответ;
уверенность первого ответа; верен ли первый ответ; есть ли истина в тройке;
истинный цвет; ответ цвета; истинный кузов; ответ кузова; примечание
```

Считай Top-1 как долю правильных первых ответов среди поддерживаемых примеров, Top-3 — долю попаданий истины в тройку. Для неизвестных классов отдельно фиксируй чужие уверенные ответы. Показывай числитель и знаменатель, например 18/30, а не только процент.

Небольшая проверка 30–50 новых фото полезна для поиска проблем. Для серьёзной оценки нужны независимый закрытый набор, достаточное количество автомобилей на класс, результаты по классам и ракурсам. Если подбираешь параметры по некоторым фото, эти фото становятся диагностическими и не должны служить единственным итоговым тестом.

## 13. Проверить точность цены

Фото само по себе не даёт правильную проверочную цену. Нужен набор объявлений с известными моделью, датой, годом, пробегом, валютой и техническими характеристиками. Цена объявления и фактическая цена сделки — разные целевые величины.

Выполни два сравнения:

1. **Цена при правильных характеристиках.** Это проверка ценовой модели.
2. **Цена после распознавания фото.** Это проверка всей цепочки с учётом ошибок распознавания.

Для сопоставления с веб-формой используй те же предположения: она не запрашивает двигатель, коробку и топливо и берёт типичные значения из справочника. Для отдельной проверки с явно известными параметрами используй CLI:

```sh
.venv/bin/python predict.py "car.jpg" 2017 85000 2.0 автомат дизель
```

Здесь `car.jpg` — существующий доверенный файл на твоём компьютере. Команда CLI читает файл и создаёт PDF; для обычной работы сайта PDF и скачивание фотографии не нужны.

Фиксируй абсолютную ошибку в GBP, относительную ошибку, MAPE, медианную относительную ошибку и попадание в диапазон. Сравнивай одинаковый рынок и уровень цен: текущий проект обучен на британских объявлениях и использует индекс из `train.py`. Конвертация в рубли не является проверкой российского рынка.

`compare_prices.py` — отдельный затратный эксперимент, которому нужны таблицы:

```sh
.venv/bin/python compare_prices.py
```

Скрипт сохраняет `price_comparison.txt` и `.csv`. Сейчас он выбирает «лучший вариант» по `MAPE test`; эту цифру нельзя считать независимой оценкой выбранного победителя. Для строгого выбора нужно использовать валидацию, а затем отдельный финальный тест. Его расширенные наборы признаков используют реальные техданные объявлений и не полностью повторяют веб-сценарий с подстановкой типичных значений.

## 14. Если что-то не работает

| Симптом | Что проверить |
|---|---|
| Страница не открывается | Запущен ли `run.py`, не закрыт ли терминал, правильны ли адрес и порт |
| Порт занят | Не запущен ли другой экземпляр; используй 7861 для отдельного запуска |
| `/api/health` показывает `error` | Первую содержательную ошибку в журнале сервера |
| Не найден модуль | Устанавливались ли зависимости через Python именно этой `.venv`; для CatBoost — ML-зависимости |
| Не найден `car_model.pt` / `price_model.joblib` | Имена, расширения, место файлов рядом с `run.py` |
| Сообщение о старой модели цены / отсутствии `specs` | Нужен новый файл CatBoost; старый переобучается через `--price-only` |
| `size mismatch`, неизвестная архитектура, нет `weights`/`members` | Совместимость новой модели с загрузчиком и списком классов; переименование файла не исправляет схему |
| Зависание на первом старте | Подготовку U2Net, доступ к официальному файлу и журнал; не запускай много копий сервера |
| После замены весов ответы прежние | Перезапущен ли сервер; используется ли правильная папка проекта |
| Пропали метрики после `--price-only` | Часть метрик не измерялась; это допустимо и должно быть явно показано |
| Обучение не видит CUDA на Mac | Текущий код выбирает CPU; для полного обучения при отсутствии CUDA есть `--cpu` |
| Распознавание ошибается без ошибки API | Это проблема качества; сохраняй случай в таблицу проверки |
| Неизвестная машина получила известное название | Текущий классификатор выбирает из своих классов; надёжного отказа пока нет |

Если появляется ошибка, запиши команду запуска, последнюю содержательную часть журнала, версию кода и контрольные суммы весов. Это поможет отличить проблему установки, несовместимость файла и ошибку качества.

## 16. Как публиковать дальнейшие изменения

Перед отправкой проверь `git status`, `git diff` и состав добавляемых файлов. Веса, датасет, `.venv`, локальные журналы и пользовательские фотографии не нужно включать в обычный коммит.

Для самостоятельной доработки удобно использовать отдельную ветку:

```sh
git switch -c my-improvement
git add docs/SETUP_AND_TESTING_RU.md
git diff --cached --check
git commit -m "Update setup and testing guide"
git push -u origin my-improvement
```

В примере публикуется только инструкция. Для изменений кода укажи конкретные изменённые файлы, выполни соответствующие тесты и создай Pull Request в `main`. Веса передавай отдельно вместе с контрольными суммами и версиями; их замена не должна терять связь с кодом и результатами проверки.
